# Kadora — Monitor de Anuncios Activos (Meta Ads)

Dashboard web (sin framework) que muestra los anuncios activos en Meta de Kadora (residencias universitarias: Granada, Barcelona, Sevilla, Zaragoza, Portugal, General). Se comparte con la jefa de Mario; sustituye una tabla de Google Sheets. Hay un **dashboard gemelo de Competencia** (`script-competencia.js`, `competencia.kadora.es`) con su propio Apps Script y su propia copia de casi todo.

## Arquitectura (3 capas independientes)

1. **Datos (lo esencial, tocar con cuidado):** un Apps Script (`obtenerAnunciosKadora`) escribe una pestaña nueva cada semana en un Google Sheet, consultando **solo** la Marketing API de Meta (`ads_read`), cuenta por cuenta. Desde 2026-07-10 no hay llamada a Ad Library / `ads_archive` ni cruce por texto: texto, fecha de inicio e imagen salen del mismo `creative` en una llamada. Residencia = mapeo fijo `account_id → residencia` (constante `AD_ACCOUNTS`, fuente de verdad de qué cuentas están activas). Un `doGet()` en ese Apps Script sirve todas las pestañas agregadas como un JSON:
   `https://script.google.com/macros/s/AKfycbyo1RZpEf9csEmcrxpLDIKumlYqb7stqULRzwxuEfPLwJ0Y00j3hsy1vJgTYKFla8ZQ/exec`
   La web consulta ese endpoint en cada carga; **no hay copia estática de los anuncios en el repo.**
2. **Frontend:** HTML/CSS/JS plano (`index.html`, `style.css`, `script.js`, `assets/`). Marca (de kadora.es): navy `#0C2340`, coral `#E56A54`, azul `#307FE2`, verde azulado `#279989`, fuente "Outfit".
3. **Despliegue:** GitHub `nhmarionicolas-sys/App-LL-Kadora` (rama `main`) → Netlify auto-deploy → `https://effortless-medovik-08e1f5.netlify.app` (link activo de la jefa desde 2026-07-13; el anterior `splendid-longma-5ecf40.netlify.app` quedó congelado al agotar el crédito gratis de Netlify). Cada `push` a `main` publica en <1 min. Credencial de GitHub en el llavero de macOS (`osxkeychain`), `git push` no pide token.

## Decisiones clave (no obvias por el código)

- **"Anuncio nuevo esta semana" = `id` de Meta que no estaba la semana anterior** (inverso de `getBajasIds`). Nunca comparar por texto ni por `fecha_inicio`: ambas variantes se probaron y descuadraban el total (`total_actual = total_anterior − bajas + nuevos`); solo comparando por `id` en ambos sentidos cuadra siempre. El KPI "🆕 Anuncios nuevos esta semana", el filtro "Solo nuevos esta semana" y el gráfico "Anuncios nuevos por semana" DEBEN usar esta definición.
- **Algunos anuncios se dejan sin imagen a propósito** (mejor nada que una imagen mala): formato Collage, posts/reels nativos de Instagram, y thumbnails que Meta solo da en 64x64. `extraerImagenCreativo` cubre imagen simple, portada de vídeo, link picture, carrusel y creatividad dinámica/Advantage+ (assets por `hash`, resueltos vía `/act_<cuenta>/adimages?hashes=[...]`; la respuesta real es `{"data":[{"url":...}]}`, no lo que dice la doc de Meta).
- **Gotcha Graph API:** pedir subcampos en `fields` (p.ej. `asset_feed_spec{images{url}}`) hace que Meta devuelva *solo* esos y omita el resto sin error. Si un campo anidado falta, comprobar primero si `fields` lo pide explícitamente. (Así estuvo roto años el soporte de creatividad dinámica: nunca se pedía `hash`.)
- **Editar/ejecutar código en el editor de Apps Script NO actualiza el Web App desplegado** (los dos proyectos). `doGet()` queda fijado a la última versión publicada; las funciones que escriben en el Sheet (`obtenerAnunciosKadora`) sí reflejan cambios al instante, pero un cambio en `doGet()` no llega a la web hasta republicar, sin ningún error que lo delate. Republicar: editor → Implementar → Gestionar implementaciones → editar (lápiz) la implementación Web App activa → Versión "Nueva versión" → Implementar. **Nunca "Nueva implementación"** (genera otra URL `/exec`).
- **`doGet()` sirve una caché en Drive, no recorre las pestañas en cada visita (desde 2026-09-03, los dos proyectos).** `reconstruirCacheAnuncios` / `reconstruirCacheCompetencia` (llamadas al final de cada extracción, en `try` aislado) montan el JSON una vez y lo guardan en Drive (`kadora_anuncios_cache.json` / `kadora_competencia_cache.json`; ids en propiedades `CACHE_FILE_ID` / `CACHE_FECHA` / `CACHE_COUNT`). `doGet()` solo lee ese archivo y aplica el filtro por clave; el JSON al frontend es **idéntico**. Si el archivo falta, `doGet()` vuelve al recorrido en vivo (nunca se rompe, como mucho sirve datos de la semana pasada). Requiere permiso de Drive y republicar el Web App.
- **Nunca colapsar anuncios con el mismo texto como "duplicados".** Cada fila con texto idéntico tiene un `id` de Meta distinto: son anuncios reales diferentes (mismo copy, distinta creatividad/audiencia). El toggle "Agrupar por texto compartido" es opcional y debe conservar conteo y enlace de cada anuncio.
- **El `access_token` de Meta nunca sale del Apps Script.** `ad_snapshot_url` lo lleva incrustado; `doGet()` lo limpia server-side (`limpiarUrlAnuncio`) reconstruyendo `https://www.facebook.com/ads/library/?id=...`. No vale limpiarlo solo en el frontend: el JSON crudo del endpoint es público.
- **El selector de semana muestra solo la semana elegida**, nunca suma varias (un bug antiguo sumaba todo y daba 117 en vez de ~63).
- **Frontend robusto ante el Web App:** Apps Script tiene arranque en frío (~10 s), salto de redirección y errores 429/500 transitorios. `loadData()` (los dos scripts) usa `fetchConReintentos()`: timeout de 15 s por intento (AbortController) + 3 intentos con backoff (2 s, 4 s) + reintento de fondo a los 10 s si fallan todos. Guard `cargandoDatos` para no solapar auto-refresh / reintento / botón manual.

## Pendiente / a vigilar

- **Tokens de Meta** en `PropertiesService` (no hardcodeados), con **dos copias**, una por proyecto (Kadora y Competencia son Apps Script separados) — actualizar siempre en los dos.
  - `ADS_READ_TOKEN` (Marketing API, app "Automatizacion creas Kadora"): System User, caducidad "Nunca". Resuelto, sin mantenimiento.
  - `META_ACCESS_TOKEN` (Ad Library, app "KADORA MONITOR", App ID `1014748534752483`): **no puede ser System User ni App Token** (falla con `OAuthException` 10 / subcódigo 2332002 — la Ad Library exige token de persona real verificada). Es un token de usuario de ~60 días, renovación **manual** (`fb_exchange_token` con el App Secret). Solo lo usa la extracción de Competencia (Kadora dejó la Ad Library el 2026-07-10): si caduca, falla Competencia, no Kadora. Renovado 2026-11-06 → **caduca 2027-01-05 12:23**. Vía fácil: Explorador de la API Graph (app KADORA MONITOR, `ads_read`) → Depurador de tokens → «Extend Access Token» → pegar en Propiedades del script de COMPETENCIA WEB (no hay que republicar). Solo Competencia usa este token.
- **Al añadir una cuenta a `AD_ACCOUNTS`, comprobar en qué Business Manager vive.** Portugal ("Liv Student Porto", `1281266735578451`) está en `Liv Student Portugal`, distinto de `LIV Student España` (donde vive `KadoraWeb`, el system user de `ADS_READ_TOKEN`). Sin acceso compartido falla con `OAuthException` 200 y no rompe la ejecución (fácil no notarlo). Arreglo: compartir la cuenta entre Business Managers (Configuración del negocio → Cuentas publicitarias → Asignar socios → Business ID destino) y asignar `KadoraWeb`; no hace falta token nuevo.
- **Migración completa Ad Library → Marketing API:** idea pendiente. Mario ve en Ads Manager más creatividades que en la Ad Library pública (p.ej. stories de Instagram). Requiere antes definir qué cuenta como "anuncio" (¿excluir stories?) y validar que la detección de nuevo/baja siga cuadrando con otra fuente de fecha.
