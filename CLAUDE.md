# Kadora — Monitor de Anuncios Activos (Meta Ads)

Dashboard web que visualiza los anuncios activos en Meta de Kadora (cadena de residencias universitarias: Granada, Barcelona, Sevilla, Zaragoza, Portugal, General), pensado para compartir con el cliente/jefa de Mario. Sustituye una tabla plana de Google Sheets por una web visual y filtrable.

## Arquitectura (tres capas independientes)

1. **Fuente de datos (no tocar sin cuidado, es lo esencial):** un Google Sheet recibe una pestaña nueva cada semana, escrita por un Apps Script (`obtenerAnunciosKadora`) que consulta **solo** la Marketing API de Meta (permiso `ads_read`), cuenta por cuenta — desde la migración del 2026-07-10 ya no hay llamada a `ads_archive`/Ad Library ni cruce por texto para esta pestaña: texto, fecha de inicio e imagen salen del mismo `creative` en una única llamada. La residencia se asigna por un mapeo fijo `account_id → residencia` (constante `AD_ACCOUNTS` en el script, fuente de verdad de qué cuentas están activas) sobre las cuentas reales de Kadora en Ads Manager: Granada, Barcelona (2 cuentas), Sevilla, Zaragoza, y desde 2026-07-13 Portugal (`1281266735578451`, cuenta "Liv Student Porto" — vive en un Business Manager de Meta distinto al resto, ver nota en "Pendiente"). Un Web App `doGet()` en ese mismo Apps Script agrega **todas** las pestañas semanales en un único JSON:
   `https://script.google.com/macros/s/AKfycbyo1RZpEf9csEmcrxpLDIKumlYqb7stqULRzwxuEfPLwJ0Y00j3hsy1vJgTYKFla8ZQ/exec`
   Este endpoint es la fuente de datos en vivo — la web lo consulta en cada carga, no hay ninguna copia estática de los anuncios en este repo.
2. **Frontend:** HTML/CSS/JS sin framework (`index.html`, `style.css`, `script.js`, carpeta `assets/`). Colores y tipografía son los reales de la marca (sacados de kadora.es): navy `#0C2340`, coral `#E56A54`, azul `#307FE2`, verde azulado `#279989`, fuente "Outfit".
3. **Despliegue:** repo de GitHub `nhmarionicolas-sys/kadora-dashboard` (rama `main`) conectado a Netlify para auto-deploy → `https://effortless-medovik-08e1f5.netlify.app` (este es el link que tiene la jefa de Mario desde el 2026-07-13; el link antiguo, `splendid-longma-5ecf40.netlify.app`, se quedó congelado en esa fecha sin recibir más actualizaciones porque esa cuenta de Netlify agotó su crédito gratuito del mes — el ciclo resetea el 2026-08-05, y si el consumo sigue creciendo esta cuenta nueva podría toparse con el mismo límite el mes que viene). Cualquier `git push` a `main` se publica solo en el link nuevo, normalmente en menos de un minuto. La credencial de GitHub está guardada en el llavero de macOS (`credential.helper=osxkeychain`), así que `git push` no debería pedir usuario/token.

## Decisiones clave (no obvias por el código)

- **"Anuncio nuevo esta semana"** se define como un `id` de Meta que no aparecía entre los anuncios de la semana anterior — mismo criterio que "anuncio de baja" (`getBajasIds`) pero en sentido inverso. Nunca comparar por texto: una primera versión lo hacía y daba un número distinto al de la variación total, lo cual confundió a Mario dos veces seguidas. Tampoco comparar por `fecha_inicio` (versión intermedia, ya corregida): un anuncio con `id` nuevo pero `fecha_inicio` igual al día de la extracción anterior no se contaba como "nuevo" aunque sí fuera una alta real, y el total dejaba de cuadrar (`total_actual ≠ total_anterior - bajas + nuevos`). Comparando por `id` en ambos sentidos, el total siempre cuadra. El KPI "🆕 Anuncios nuevos esta semana", el filtro "Solo nuevos esta semana" y el gráfico "Anuncios nuevos por semana" DEBEN seguir usando esta misma definición.
- **Algunos anuncios se quedan sin imagen a propósito** (se prefiere no mostrar nada antes que una imagen incorrecta o pixelada): formato "Collage" de Meta, posts/reels de Instagram compartidos como anuncio, y thumbnails que Meta solo expone en 64x64 sin alternativa de mejor calidad. `extraerImagenCreativo` cubre imagen simple, portada de vídeo, link picture, carrusel, y creatividad dinámica/Advantage+ (imágenes y vídeos referenciados por `hash` en vez de `url`, resueltos vía `/act_<cuenta>/adimages?hashes=[...]`; la respuesta real es `{"data":[{"url":...}]}`, no el `{"images":{hash:...}}` que sugiere la documentación de Meta). **Gotcha de la Graph API confirmado el 2026-07-13:** pedir subcampos específicos en `fields` (p.ej. `asset_feed_spec{images{url}}`) hace que Meta devuelva *solo* esos subcampos y omita el resto en silencio, sin error — así estuvo roto el soporte de creatividad dinámica desde que se escribió, porque nunca se pedía `hash`. Si un campo anidado parece faltar en la respuesta, comprobar primero si `fields` lo está pidiendo explícitamente antes de asumir que Meta no lo tiene. Lo que sigue quedando fuera: formato Collage (estructura no investigada) y contenido nativo de Instagram (requiere permisos de Instagram Graph API que no se tienen).
- **Editar y ejecutar código en el editor de Apps Script NO actualiza el Web App ya desplegado** (aplica a los dos Apps Script, Kadora y Competencia). El `doGet()` que sirve el JSON en la URL `/exec` queda fijado a la versión publicada en el último despliegue — pegar un `Code.gs` nuevo y darle a "Ejecutar" en el editor corre esa función con el código más reciente de verdad (por eso `obtenerAnunciosKadora`, que escribe directo en el Sheet, sí refleja cambios al momento), pero cualquier cambio dentro de `doGet()` no llega a la web hasta republicar el despliegue — mientras tanto el Sheet ya tiene el dato nuevo, pero el JSON público sigue sin él, sin ningún error que lo delate. Confirmado 2026-07-31 al añadir el campo `campania`: la columna ya estaba en el Sheet con datos reales, pero la clave `campania` faltaba del todo en el JSON de `/exec`. Arreglo: en el editor, Implementar → Gestionar implementaciones → editar (icono lápiz) la implementación activa de tipo Web App → Versión: "Nueva versión" → Implementar. **Nunca usar "Nueva implementación" para esto** — genera una URL `/exec` distinta de la que ya usa la web.
- **`doGet()` sirve una caché en Drive, no recorre las pestañas en cada visita (desde 2026-09-03, en los dos Apps Script).** Antes `doGet()` leía *todas* las pestañas semanales y montaba el JSON en cada carga de la web; con el histórico creciendo eso se volvía lento y podía llegar a agotar el límite de ejecución del Web App. Ahora `construirAllDataDesdeSheets_()` (Kadora) / `construirDatosDesdeSheets_()` (Competencia) hace ese recorrido una sola vez al final de cada extracción (`obtenerAnunciosKadora` / `obtenerAnunciosCompetencia` llaman a `reconstruirCacheAnuncios` / `reconstruirCacheCompetencia` en un `try` aislado) y guarda el JSON en un archivo de Drive (`kadora_anuncios_cache.json` / `kadora_competencia_cache.json`; el id se cachea en la propiedad `CACHE_FILE_ID`, más `CACHE_FECHA` y `CACHE_COUNT`). `doGet()` solo lee ese archivo y luego aplica el filtro por clave de acceso igual que antes; el JSON que recibe el frontend es **idéntico**. Si el archivo falta o no se puede leer, `doGet()` vuelve solo al recorrido en vivo de las pestañas (comportamiento anterior) — nunca se rompe, como mucho sirve datos de la semana pasada. El chequeo de salud del lunes ya compara el total de la web con el del Sheet, así que una caché desincronizada saldría como aviso amarillo. Requiere el permiso de Drive en el proyecto (se acepta la primera vez que se ejecuta `reconstruirCache*`) y **republicar el Web App** ("Nueva versión") como cualquier cambio en `doGet()`.
- **Nunca colapsar/ocultar anuncios con el mismo texto como si fueran "duplicados".** Se comprobó con datos reales que cada fila con texto idéntico tiene un ID de anuncio de Meta distinto — son anuncios activos genuinamente diferentes (mismo copy, distinta creatividad/audiencia/ubicación). El toggle "Agrupar por texto compartido" es opcional y, aun agrupando, debe conservar el conteo real y el enlace de cada anuncio individual.
- **El `access_token` de Meta nunca debe salir del Apps Script.** `ad_snapshot_url` de la API de Meta lleva el token incrustado; `doGet()` lo limpia server-side (función `limpiarUrlAnuncio`) reconstruyendo un enlace público `https://www.facebook.com/ads/library/?id=...`. No basta con limpiarlo solo en el frontend, porque el JSON crudo del endpoint es público.
- El selector de semana muestra **solo** los datos de la semana elegida — nunca se suman varias semanas por defecto (un bug anterior sumaba todas las pestañas y daba 117 en vez de los ~63 activos reales de esa semana).

## Pendiente / a vigilar

- Ambos tokens de Meta viven en `PropertiesService`, no hardcodeados — y hay que actualizarlos **en los dos Apps Script** (Kadora y Competencia tienen cada uno su propia copia de `META_ACCESS_TOKEN`, son proyectos separados). `ADS_READ_TOKEN` (Marketing API, app "Automatizacion creas Kadora") es un token de **Usuario del sistema (System User)** con caducidad "Nunca" — resuelto, no requiere mantenimiento. `META_ACCESS_TOKEN` (Ad Library, app "KADORA MONITOR") **no puede ser System User ni App Token**: probado el 2026-07-09 y falla con `OAuthException` código 10 / subcódigo 2332002 ("Application does not have permission for this action") — la Ad Library API de Meta exige que el token pertenezca a una persona real verificada, no a una identidad de negocio. Este token debe seguir siendo un token de Usuario personal de larga duración (~60 días) y toca renovarlo a mano cada vez que caduque, en los dos scripts. **Renovado el 2026-09-03** (intercambio `fb_exchange_token` con el App Secret de "KADORA MONITOR", App ID `1014748534752483`; el token de System User también se probó de nuevo y sigue fallando) — caduca alrededor del **2026-11-02**. Recordatorio automático de un solo disparo para el **2026-10-30** (rutina `trig_01FQz8Any5cHTCDkXruH6a7X` en claude.ai/code/routines) que manda email a `mario.nunez@litenlemon.com` con los pasos de renovación en los dos scripts. La rutina anterior (`trig_01TqznJUj6HcWgEB2iMksdyk`, del 2026-09-02) ya está disparada y desactivada.
- Mario tiene acceso a Ads Manager de Kadora pero ve ahí bastantes más creatividades de las que aparecen en la Ad Library pública (incluye stories de Instagram, que la Ad Library no muestra). Se ha planteado migrar la fuente de datos completa de la Ad Library a la Marketing API directamente — no implementado aún, requiere antes definir qué tipos de contenido cuentan como "anuncio" (¿excluir stories?) y validar que la detección de nuevo/baja siga siendo coherente con otra fuente de fecha.
- **Al añadir una cuenta nueva a `AD_ACCOUNTS`, comprobar antes en qué Business Manager de Meta vive.** Pasó con Portugal (2026-07-13): la cuenta "Liv Student Porto" está en un Business Manager distinto (`Liv Student Portugal`) al del resto de Kadora (`LIV Student España`, donde vive `KadoraWeb`, el system user de `ADS_READ_TOKEN`). Sin acceso compartido, esa cuenta falla con `OAuthException` código 200 ("Ad account owner has NOT grant ads_read permission") mientras las demás cuentas funcionan con normalidad — es fácil no notarlo porque no rompe la ejecución. Arreglo: compartir la cuenta entre Business Manager (Configuración del negocio → Cuentas publicitarias → Asignar socios → Business ID de destino) y luego asignar `KadoraWeb` a la cuenta ya compartida; no hace falta system user ni token nuevos.

## Cómo probar cambios

No hay build ni dependencias. Para ver cambios en local:
```
cd ~/Desktop/kadora-dashboard && python3 -m http.server 8931
```
y abrir `http://localhost:8931`.

**Publicar en lotes, no cambio a cambio (desde 2026-07-13):** cada `git push` a `main` dispara un deploy de producción en Netlify, y la cuenta de Netlify funciona con un crédito mensual limitado (la cuenta original se quedó sin crédito por publicar demasiado seguido, obligando a migrar de cuenta el 2026-07-13). Por eso: seguir haciendo `git commit` en local con normalidad después de cada cambio probado, pero **no hacer `git push`** hasta acumular varios cambios y que Mario confirme que quiere publicar el lote. `git add -A && git commit -m "..."` tantas veces como haga falta; `git push` solo al final, una vez.
