# Kadora — Monitor de Anuncios Activos (Meta Ads)

Dashboard web que visualiza los anuncios activos en Meta de Kadora (cadena de residencias universitarias: Granada, Barcelona, Sevilla, Zaragoza, General), pensado para compartir con el cliente/jefa de Mario. Sustituye una tabla plana de Google Sheets por una web visual y filtrable.

## Arquitectura (tres capas independientes)

1. **Fuente de datos (no tocar sin cuidado, es lo esencial):** un Google Sheet recibe una pestaña nueva cada lunes, escrita por un Apps Script (`obtenerAnunciosKadora`) que llama a la Meta Graph API (`ads_archive`) para el page id `100149119120066` (texto, fecha de inicio, link). Ese mismo script hace además una consulta aparte a la Marketing API (permiso `ads_read`) sobre las 6 cuentas publicitarias reales de Kadora en Ads Manager (`655249645959790`, `550388136263110`, `1060996941437123`, `841600361572302`, `1309925056255281`, `1674463280079393`) para conseguir la imagen de cada anuncio, cruzando por texto normalizado — no existe forma de cruzar por id porque el id de la Ad Library y el id interno de Marketing API son namespaces distintos e incompatibles (confirmado probando ambos con el mismo token). Un Web App `doGet()` en ese mismo Apps Script agrega **todas** las pestañas semanales en un único JSON:
   `https://script.google.com/macros/s/AKfycbyo1RZpEf9csEmcrxpLDIKumlYqb7stqULRzwxuEfPLwJ0Y00j3hsy1vJgTYKFla8ZQ/exec`
   Este endpoint es la fuente de datos en vivo — la web lo consulta en cada carga, no hay ninguna copia estática de los anuncios en este repo.
2. **Frontend:** HTML/CSS/JS sin framework (`index.html`, `style.css`, `script.js`, carpeta `assets/`). Colores y tipografía son los reales de la marca (sacados de kadora.es): navy `#0C2340`, coral `#E56A54`, azul `#307FE2`, verde azulado `#279989`, fuente "Outfit".
3. **Despliegue:** repo de GitHub `nhmarionicolas-sys/kadora-dashboard` (rama `main`) conectado a Netlify para auto-deploy → `https://splendid-longma-5ecf40.netlify.app` (este es el link que ya tiene la jefa de Mario). Cualquier `git push` a `main` se publica solo en ese link, normalmente en menos de un minuto. La credencial de GitHub está guardada en el llavero de macOS (`credential.helper=osxkeychain`), así que `git push` no debería pedir usuario/token.

## Decisiones clave (no obvias por el código)

- **"Anuncio nuevo esta semana"** se define como un `id` de Meta que no aparecía entre los anuncios de la semana anterior — mismo criterio que "anuncio de baja" (`getBajasIds`) pero en sentido inverso. Nunca comparar por texto: una primera versión lo hacía y daba un número distinto al de la variación total, lo cual confundió a Mario dos veces seguidas. Tampoco comparar por `fecha_inicio` (versión intermedia, ya corregida): un anuncio con `id` nuevo pero `fecha_inicio` igual al día de la extracción anterior no se contaba como "nuevo" aunque sí fuera una alta real, y el total dejaba de cuadrar (`total_actual ≠ total_anterior - bajas + nuevos`). Comparando por `id` en ambos sentidos, el total siempre cuadra. El KPI "🆕 Anuncios nuevos esta semana", el filtro "Solo nuevos esta semana" y el gráfico "Anuncios nuevos por semana" DEBEN seguir usando esta misma definición.
- **La imagen de cada anuncio puede no coincidir 100% con la creatividad real**, porque se asigna cruzando por texto contra la Marketing API (ver arriba) en vez de por id. Cuando varios anuncios comparten texto exacto se desambigua por fecha de creación más cercana (sin repetir la misma imagen dos veces), pero el cruce puede fallar — especialmente en textos cortos o genéricos. Si Mario reporta una imagen que no se corresponde con el anuncio real al abrir su link, es este mecanismo, no un bug de renderizado.
- **Algunos anuncios se quedan sin imagen a propósito** (se prefiere no mostrar nada antes que una imagen incorrecta o pixelada): formato "Collage" de Meta, posts/reels de Instagram compartidos como anuncio, y thumbnails que Meta solo expone en 64x64 sin alternativa de mejor calidad. `extraerImagenCreativo` ya cubre imagen simple, portada de vídeo, link picture, carrusel y creativo dinámico — lo que queda fuera son formatos cuya estructura de datos en Marketing API no se ha investigado (Collage) o que requieren permisos de Instagram Graph API que no se tienen (`ads_read` no basta para leer contenido nativo de Instagram).
- **Nunca colapsar/ocultar anuncios con el mismo texto como si fueran "duplicados".** Se comprobó con datos reales que cada fila con texto idéntico tiene un ID de anuncio de Meta distinto — son anuncios activos genuinamente diferentes (mismo copy, distinta creatividad/audiencia/ubicación). El toggle "Agrupar por texto compartido" es opcional y, aun agrupando, debe conservar el conteo real y el enlace de cada anuncio individual.
- **El `access_token` de Meta nunca debe salir del Apps Script.** `ad_snapshot_url` de la API de Meta lleva el token incrustado; `doGet()` lo limpia server-side (función `limpiarUrlAnuncio`) reconstruyendo un enlace público `https://www.facebook.com/ads/library/?id=...`. No basta con limpiarlo solo en el frontend, porque el JSON crudo del endpoint es público.
- El selector de semana muestra **solo** los datos de la semana elegida — nunca se suman varias semanas por defecto (un bug anterior sumaba todas las pestañas y daba 117 en vez de los ~63 activos reales de esa semana).

## Pendiente / a vigilar

- Ambos tokens de Meta (`META_ACCESS_TOKEN` para la Ad Library y `ADS_READ_TOKEN` para la Marketing API) ya viven en `PropertiesService` del Apps Script, no hardcodeados. Pendiente: `ADS_READ_TOKEN` se generó como token de usuario normal vía Graph API Explorer (caduca pronto, o a los ~60 días si se marcó "no caduca"), no como token de **Usuario del sistema (System User)** — convendría sustituirlo por uno de System User para que no haya que regenerarlo. El `META_ACCESS_TOKEN` original de Mario estuvo expuesto en texto plano en el pasado; sigue pendiente rotarlo por el mismo motivo.
- Mario tiene acceso a Ads Manager de Kadora pero ve ahí bastantes más creatividades de las que aparecen en la Ad Library pública (incluye stories de Instagram, que la Ad Library no muestra). Se ha planteado migrar la fuente de datos completa de la Ad Library a la Marketing API directamente — no implementado aún, requiere antes definir qué tipos de contenido cuentan como "anuncio" (¿excluir stories?) y validar que la detección de nuevo/baja siga siendo coherente con otra fuente de fecha.

## Cómo probar cambios

No hay build ni dependencias. Para ver cambios en local:
```
cd ~/Desktop/kadora-dashboard && python3 -m http.server 8931
```
y abrir `http://localhost:8931`. Para publicarlos: `git add -A && git commit -m "..." && git push` (Netlify despliega solo).
